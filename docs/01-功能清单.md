# FlowYoga 功能清单

本文确定毕业设计第一期的业务范围。系统名称沿用 FlowYoga，场景是单门店瑜伽馆，第一期只做团体课程和会员次卡。

## 1. 角色

| 角色 | 使用人 | 核心功能 |
| --- | --- | --- |
| 管理员 | 馆内运营人员 | 会员管理、教练管理、课程和教室管理、排课、开卡、运营统计 |
| 教练 | 授课教练 | 查看个人课表、查看预约名单、登记签到、查看授课记录 |
| 会员 | 持卡会员 | 查看课程和课表、预约与取消、查看会员卡和剩余次数、查看上课记录 |

一个账号只属于一个角色。管理员、教练、会员分别登录后进入各自的页面。

## 2. 本期要完成的功能

### 2.1 管理员

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-ADM-01 | 登录 | 使用账号密码登录，获得带角色的访问令牌 |
| F-ADM-02 | 会员建档 | 维护会员姓名、手机号、状态；停用后不能预约 |
| F-ADM-03 | 教练建档 | 维护教练姓名、手机号、状态；停用后不能再排新课 |
| F-ADM-04 | 课程管理 | 维护团体课程名称、难度、默认时长和简介 |
| F-ADM-05 | 教室管理 | 维护教室名称、容纳人数和可用状态 |
| F-ADM-06 | 排课 | 为课程指定教练、教室、起止时间和可预约名额 |
| F-ADM-07 | 排课冲突提示 | 教练或教室时间重叠时拒绝保存，并说明冲突对象和时间 |
| F-ADM-08 | 取消整节课 | 开课前取消课次，已预约未核销的课次退回 |
| F-ADM-09 | 次卡套餐 | 维护套餐名称、包含次数、有效天数和标价 |
| F-ADM-10 | 开卡 | 为会员发放一张次卡，记录线下收款金额，不接在线支付 |
| F-ADM-11 | 运营统计 | 查看预约率、出勤率、课次消耗，并能够和业务记录核对 |

### 2.2 教练

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-COA-01 | 登录 | 只能进入教练页面 |
| F-COA-02 | 个人课表 | 只显示分配给自己的课次 |
| F-COA-03 | 预约名单 | 查看自己课次上的预约会员 |
| F-COA-04 | 登记签到 | 只能给自己的课次签到，签到后核销一次课次 |
| F-COA-05 | 授课记录 | 查看自己已结束课次的签到和缺席结果 |

### 2.3 会员

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-MEM-01 | 登录 | 只能进入会员页面 |
| F-MEM-02 | 查看课程和课表 | 查看可预约的团体课次 |
| F-MEM-03 | 预约 | 选择课次并占用一次课次，名额同时减少 |
| F-MEM-04 | 取消 | 仅在允许的截止时间前取消，并释放名额和课次 |
| F-MEM-05 | 会员卡 | 查看持有的次卡、剩余次数和有效期 |
| F-MEM-06 | 上课记录 | 查看已预约、已签到、缺席和已取消的记录 |

### 2.4 系统能力

| 编号 | 能力 | 说明 |
| --- | --- | --- |
| F-SYS-01 | 统一入口 | 浏览器只访问网关 |
| F-SYS-02 | 服务注册 | 业务服务和网关注册到 Nacos |
| F-SYS-03 | 入口认证与服务内鉴权 | 网关校验令牌，业务服务再次校验角色和数据归属 |
| F-SYS-04 | 并发预约 | 最后一个名额只会被一个请求占走 |
| F-SYS-05 | 重复提交 | 同一会员对同一课次连续点击，只保留一条有效预约 |
| F-SYS-06 | 课次一致性 | 预约占用、签到核销、取消释放可以在超时和重启后核对 |
| F-SYS-07 | 请求标识 | 一次访问在网关和下游日志中使用同一个请求编号 |
| F-SYS-08 | 健康检查与部署 | 服务提供健康检查，能够按说明在干净环境启动 |

## 3. 必须跑通的主流程

管理员排课 → 会员开卡 → 会员预约 → 教练签到 → 课次核销 → 管理员查看统计。

对应的异常路径也要有确定结果：预约时会员卡服务超时，不能告诉会员预约成功；服务恢复后，能按预约编号核对是占用成功、占用失败，还是仍在处理中。

## 4. 本期明确不做

| 项目 | 处理方式 |
| --- | --- |
| 真实在线支付 | 开卡只记录线下收款金额 |
| 多门店 | 默认只有一家馆，数据模型不引入门店切换 |
| 私教套餐 | 只做团体课 |
| 小程序 | 第一期使用 Vue 管理端和会员端页面 |
| 储值卡、期限卡 | 只做按次扣除的次卡 |
| Sentinel 限流熔断 | 放到 2027 年 1 月的服务治理阶段 |
| Redis | 出现明确的缓存或会话需求后再引入 |

## 5. 验收时要拿出的证据

- 权限：会员调用管理员接口被拒绝；教练不能给其他教练的课签到。
- 并发：100 个并发请求竞争 10 个名额，有效预约最多 10 个，且没有重复占用课次。
- 故障恢复：会员卡服务不可用或调用超时时，接口不返回预约成功；恢复后核对结果与流水一致。
- 部署：按部署说明在干净环境启动，导入演示数据并完成主流程。
- 统计：预约率、出勤率、课次消耗能逐项对上预约、签到和课次流水。

页面能点击只是演示的一部分，上述证据需要留在测试报告里。
