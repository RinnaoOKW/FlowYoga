# 技术验证

验证日期：2026-10-12。这一步只证明版本能一起启动，并跑通一次跨服务调用。业务数据、登录和页面不在这次验证里。

## 1. 锁定版本

Spring Cloud Alibaba 的官方版本说明把 2025.1.x 对应到 Spring Boot 4.0.x 和 Spring Cloud 2025.1.x。2026 年 10 月 12 日，Maven Central 上该产品线唯一的正式版本是 2025.1.0.0，发布说明里写明适配：

| 组件 | 锁定版本 |
| --- | --- |
| JDK | 21 |
| Spring Boot | 4.0.0 |
| Spring Cloud | 2025.1.0 |
| Spring Cloud Alibaba | 2025.1.0.0 |
| Nacos Server / Client | 3.1.1 |
| Sentinel | 1.8.9（本期不引入） |

2025.1.0.1 当时仍是快照，没有采用。Spring Cloud 2025.1.1 能配合更高的 Boot 4.0 补丁，但 Spring Cloud Alibaba 2025.1.0.0 声明的是 Spring Cloud 2025.1.0 和 Spring Boot 4.0.0。后续只有在官方兼容表给出新的一整套正式版本时才升级。

- https://sca.aliyun.com/docs/2025.x/overview/version-explain/

## 2. 本次验证的调用链

```text
接口工具
  -> flowyoga-gateway:17080
  -> flowyoga-course:17083
  -> flowyoga-member:17082  /internal/member-cards/probe
```

课程服务使用 OpenFeign 和 LoadBalancer，通过 Nacos 找到会员卡服务。网关生成或透传 `X-Request-Id`，课程服务把它继续传给会员卡服务。会员卡服务的内部接口要求 `X-Internal-Token`，浏览器路径不转发 `/internal/**`。

探针返回的剩余次数是固定值，用来证明服务可达，不代表真实会员卡。

## 3. 启动方式

```powershell
docker compose up -d
.\scripts\start-dev.ps1
.\scripts\verify-chain.ps1
```

如果 Docker Hub 下载很慢，可以先从可用镜像源拉取再打上原标签：

```powershell
docker pull docker.m.daocloud.io/nacos/nacos-server:v3.1.1
docker tag docker.m.daocloud.io/nacos/nacos-server:v3.1.1 nacos/nacos-server:v3.1.1
```

Nacos 3.1.1 的就绪检查是 `GET http://127.0.0.1:8080/v3/console/health/readiness`。旧的 `/nacos/v1/console/health/readiness` 会返回 410。客户端端口 8848 上也可以看 `GET /nacos/actuator/health`。

Nacos 在本机编排里关闭了鉴权，只适合开发机。8848 和 8080 不要暴露到公网。

## 4. 验证结果

2026-10-12 本机调用通过。Docker 拉取 `nacos/nacos-server:v3.1.1` 时镜像层传输中断，本机没有该镜像。这次改用官方同版本发行包 `nacos-server-3.1.1` 以 standalone 方式启动，端口仍是 8080、8848、9848。`docker-compose.yml` 继续作为后续部署入口。

四个服务都注册到 Nacos，服务列表为 `flowyoga-gateway`、`flowyoga-user`、`flowyoga-member`、`flowyoga-course`。

`GET http://127.0.0.1:17080/api/course/integration/member-card`，请求头 `X-Request-Id: chain-test-001`，返回 200，响应头为同一个请求编号，正文为：

```json
{
  "path": "gateway -> flowyoga-course -> flowyoga-member",
  "courseService": "flowyoga-course",
  "requestId": "chain-test-001",
  "memberCard": {
    "service": "flowyoga-member",
    "probe": true,
    "cardType": "SESSION_CARD",
    "remainingSessions": 10,
    "requestId": "chain-test-001",
    "message": "会员卡服务可达。这是固定探针数据，不是会员的真实剩余次数。"
  }
}
```

同一网关还返回了 `/api/gateway/status`、`/api/user/status`、`/api/member/status`。会员卡返回的剩余次数是固定探针数据。单元测试 `mvn test` 已通过。

## 5. 2026-10-13 评审修正与验证

本次修正第一阶段的运行脚本与业务设计，未提前实现数据库、登录或预约业务接口。

- 启动脚本先打包，再通过 `java -jar` 启动服务，逐个保存 JVM 的 PID、启动时间、jar 路径和工作区；记录文件通过同目录临时文件替换，部分启动失败时已记录的服务仍可停止，未能记录的本次新进程单独清理。
- 停止脚本只处理当前工作区的启动记录，同时检查实际进程身份与启动时间，不按端口或服务名称批量结束进程。PID 复用与其他工作区的同名进程被跳过；信息读取或停止失败时保留记录，并返回失败供重试。
- 签到改为本地登记到场，未取消的课程结束后核销；开课前场馆取消时，提前签到的预约也释放占用。功能清单、业务规则、状态图、服务边界、统计口径和开题提纲同步更新。
- 预约确认等待最多 120 秒且不跨越开课时间，超时或课次取消后关闭预约并释放名额。返还任务持久保存，会员卡服务支持先释放封存编号，防止迟到的占用重新扣次。
- 开卡明确分别保存套餐标价快照与实际收款金额，另存收款时间、操作管理员和金额差异原因。
