# 三角色登录与接口约定

## 1. 页面与身份

| 身份 | 登录入口 | 登录后入口 | 本地演示账号 |
| --- | --- | --- | --- |
| 管理员 | `/login/admin` | `/admin/members`（`/admin` 自动跳转） | `admin` |
| 教练 | `/login/coach` | `/coach` | `coach` |
| 会员 | `/login/member` | `/member` | `member` |

本地演示密码均为 `FlowYoga@123`。只有 `flowyoga.demo.enabled=true` 时用户服务才创建演示账号，已有账号不会被重置。前端演示填充按钮只在开发模式显示。管理员进入会员与教练管理工作台；会员和教练欢迎页展示真实的当前账号、身份、手机号、权限和登录有效期，其他业务功能按后续迭代开放。

身份按钮用于选择入口，不能授予权限。后端同时验证账号、密码、启用状态与请求身份；会员账号即使选择管理员入口也登录失败。直接访问另一个角色的欢迎页由前端路由转回自己的空间，直接请求对应后台接口则返回 403。

## 2. 请求与响应

浏览器请求统一使用 `/api`，本地 Vite 将其代理到网关 17080。前端不直接访问用户、会员或课程服务端口，不在 localStorage/sessionStorage 中保存认证令牌。

| 方法与路径 | 认证要求 | 行为 |
| --- | --- | --- |
| GET `/api/user/auth/csrf` | 公开 | 返回 `headerName` 与 CSRF `token`，同时设置 CSRF Cookie |
| POST `/api/user/auth/login` | CSRF | 校验账号密码及身份；设置认证 Cookie，返回当前用户和 `expiresAt` |
| GET `/api/user/auth/me` | 登录 | 返回当前用户及会话到期时间，服务端核查会话与账号状态 |
| POST `/api/user/auth/logout` | 登录 + CSRF | 撤销当前会话，清除认证 Cookie，返回 204 |
| GET `/api/user/workspaces/admin` | ADMIN | 管理员欢迎页的身份数据 |
| GET `/api/user/workspaces/coach` | COACH | 教练欢迎页的身份数据 |
| GET `/api/user/workspaces/member` | MEMBER | 会员欢迎页的身份数据 |

登录请求：

```json
{"loginName":"member","password":"FlowYoga@123","role":"MEMBER"}
```

成功响应结构：

```json
{
  "user": {
    "id": "3001",
    "loginName": "member",
    "displayName": "瑜伽会员",
    "phone": "13000000003",
    "role": "MEMBER",
    "roleLabel": "会员",
    "status": "ACTIVE",
    "permissions": ["booking:own", "card:own", "schedule:read"]
  },
  "expiresAt": "带 UTC 时区的实际到期时间"
}
```

用户编号为字符串，响应不包含密码摘要或 JWT 本体。失败统一返回 `{code,message}`：400 为格式错误，401 为未登录或账号、密码、身份不匹配，403 为无权限或 CSRF 校验失败。网络不可用时页面显示可重试错误并恢复按钮，不能假报登录成功。

## 3. Cookie、会话与权限

- `FLOWYOGA_AUTH`：JWT Cookie，HttpOnly、SameSite=Lax、Path=/、有效期 30 分钟。生产 HTTPS 时设置 `FLOWYOGA_SECURE_COOKIE=true`。
- JWT 使用 HS256，签名密钥由本地初始化随机生成，至少 32 字节；issuer 固定 `flowyoga-user`，audience 固定 `flowyoga-web`，包含 sub、jti、role、iat、exp。
- 用户服务通过 MyBatis 读取用户和角色权限，并再次检查有效会话、停用状态与真实角色。退出后的原始令牌不能再读取当前用户或欢迎页。
- 网关检查签名、时间、issuer、audience 和角色；用户服务再次检查会话和角色。角色或用户编号请求头不构成身份依据。
- Cookie 认证的 POST 操作由用户服务执行 CSRF 校验。前端每次写操作前获取 CSRF 令牌，并放在返回的指定请求头中；登录、退出后令牌重新获取。
- 公开登录与 CSRF 端点忽略旧认证 Cookie，避免过期会话阻止重新登录。
- 第三阶段的会员、课程业务接口必须在所属服务加入角色、数据归属与会话有效性检查；网关校验不能替代服务内授权。

第一阶段的公开状态接口与固定调用探针保留用于本机开发验证；它们不提供真实会员数据。

## 4. 启动与验收

```powershell
.\scripts\start-stage2.ps1
# 已完成打包和 npm ci 时可以省略构建：
.\scripts\start-stage2.ps1 -SkipBuild
.\scripts\verify-database.ps1
.\scripts\stop-stage2.ps1
```

需要 MySQL 8.0.16+、JDK 21、Maven 3.9、Node.js 20.19+ 或 22.12+、Nacos 3.1.1。当前脚本的默认 MySQL 与 Node 安装目录适配本机，换电脑时分别用 `-MySqlHome`、`-NodePath` 指定。服务和数据库的后台进程均记录 PID 与启动时间，不按端口批量结束进程。Nacos 可复用已有实例，未运行时使用 Docker 编排。

| 验收项 | 预期 |
| --- | --- |
| 三角色正确账号登录 | 进入各自欢迎页，显示数据库中的实际身份 |
| 正确密码但身份选错 | 401，页面显示错误，不进入错误角色空间 |
| 未登录直接请求个人资料或角色接口 | 401 |
| 会员请求管理员/教练接口 | 403 |
| 请求头伪造角色、篡改 JWT、账号停用、会话过期 | 拒绝访问 |
| 无 CSRF 的登录或退出请求 | 拒绝写操作 |
| 刷新页面 | 重新核实会话并保留有效登录 |
| 退出后重放原令牌 | 用户服务返回 401 |
| 桌面与窄屏操作 | 表单可读、角色切换、密码显隐、错误提示和键盘提交可用 |

技术依据：[MyBatis 4.0 兼容说明](https://mybatis.org/spring-boot-starter/mybatis-spring-boot-autoconfigure/)、[Spring Security JWT](https://docs.spring.io/spring-security/reference/servlet/oauth2/resource-server/jwt.html)、[Spring Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。
