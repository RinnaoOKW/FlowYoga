# 管理员：会员与教练管理

## 页面和操作

管理员登录后默认进入 `/admin/members`，侧栏可切换 `/admin/coaches`。列表、总人数、启用人数和停用人数均读取数据库；姓名、手机号或登录账号可搜索，状态可筛选，列表每页 10 条。教练列表另显示教学专长，编辑表单可维护简介。

新增时填写姓名、手机号、登录账号、初始密码和初始状态。账号为 3–50 位字母、数字、点、下划线或短横线；手机号为 11 位大陆手机号，在三类账号中全局唯一；密码至少 8 位且 UTF-8 编码不超过 72 字节。登录账号建立后不在档案编辑中修改。密码只传给用户服务做 BCrypt，不写入同步任务，不返回到列表。

停用和启用需要确认。停用会同时关闭账号登录，撤销该账号已有会话；重新启用后需重新登录，旧令牌不能恢复。会员档案、教练档案和历史业务均保留。停用会员不能新预约，停用教练不能排入新课；预约与排课接口后续实现时仍须检查档案状态。

## 对外接口

两组接口分别由会员服务和课程服务提供，经网关访问，均要求管理员身份。直接访问业务服务也校验签名、角色和用户服务中的有效会话；请求头中的用户编号或角色不构成身份。

| 操作 | 会员接口 | 教练接口 |
| --- | --- | --- |
| 查询列表 | GET `/api/member/admin/members` | GET `/api/course/admin/coaches` |
| 新增 | POST `/api/member/admin/members` | POST `/api/course/admin/coaches` |
| 编辑 | PUT `/api/member/admin/members/{id}` | PUT `/api/course/admin/coaches/{id}` |
| 启用/停用 | PATCH `/api/member/admin/members/{id}/status` | PATCH `/api/course/admin/coaches/{id}/status` |
| 重试同步 | POST `/api/member/admin/members/changes/{requestId}/retry` | POST `/api/course/admin/coaches/changes/{requestId}/retry` |

列表参数为 `keyword`、`status`（空 / ACTIVE / DISABLED）、`page`（从 1 起）、`size`（1–50，页面取 10）。响应为 `items`、筛选后的 `total`、`page`、`size`、全体已完成建档账号的 `statistics` 及当前 `pendingChanges`。列表返回档案编号 `id` 和用户编号 `userId`，都是字符串；`createdAt` 为 UTC，页面按上海时间显示。搜索中的 `%`、`_` 按文字处理，不作为通配符。

新增请求例子：

```json
{
  "requestId": "每次操作新生成的 UUID，重试同一操作时保持不变",
  "loginName": "studio.member01",
  "initialPassword": "由管理员设置的初始密码",
  "displayName": "示例会员",
  "phone": "13900000001",
  "status": "ACTIVE",
  "specialty": null,
  "introduction": null
}
```

编辑提交姓名、手机号、教练专长/简介，以及当前列表的 `version` 和新 `requestId`；状态修改提交 `status`、`version`、`requestId`。不匹配的版本返回 409，提示刷新后编辑。相同编号、不同资料返回 409；同一档案尚在同步时拒绝开始另一项变更。

成功返回 `{requestId,state:"DONE",personId,message}`，新增为 201，其他为 200。结果不确定时为 202，`state` 是 PENDING 或 ACCOUNT_CREATED，页面明确显示同步处理中。格式错误为 400，未认证为 401，无角色权限或无 CSRF 校验为 403，重复账号/手机号或版本冲突为 409，读取账号服务失败为 503。

## 跨服务保存与恢复

姓名、手机号、角色与密码属于用户服务；会员档案属于会员服务；教练专长与简介属于课程服务。三个服务只访问自己的数据库，通过 Nacos 注册发现和 OpenFeign 通信。

1. 档案服务先持久保存操作编号和不含密码的资料快照，并获得 60 秒任务租约。
2. 新增先在用户服务建立 **DISABLED** 账号和 PREPARED 记录，随后在档案服务的本地事务中建立档案并记录 ACCOUNT_CREATED，最后在用户服务启用账号、把账号变更记为 APPLIED，再把档案任务记为 DONE。档案还没有保存时，账号不能登录。
3. 编辑与状态变更先由用户服务在本地事务中保存账号修改与 APPLIED 操作回执，再由档案服务在本地事务中更新档案版本并完成任务。中断时任务保持未完成，页面不声称全部成功；后台按相同编号恢复。
4. 初始密码不持久保存。新增请求超时后，后台按原编号查询账号回执；有回执就继续建档，没有回执则在用户服务原子地关闭该编号。ABORTED 封存记录与迟到的新增共用唯一主键，阻止晚到请求建立可用账号。只可关闭原编号新建且未完成的账号，不能按手机号停用其他人，也不能撤回已完成的建档。

后台每 5 秒扫描持久任务，失败按 5、10、20、40、80、160、300 秒、随后每 300 秒重试；不会因次数达到上限丢弃任务。服务重启后可回收过期租约。管理员可在同步面板手动重试。同一账号修改在用户服务有回执，相同编号重试不会覆盖后来已经接受的修改。

`account_change` 是用户库新增的第 6 张业务表，共 18 张业务表。会员/教练档案增加 `version`，原账号任务表补充操作、资料快照、指纹、预期版本与租约。三个数据库均由 Flyway 管理迁移；原来已经建好的会员/课程库以 V1 建立基线，再执行 V2，空库会依次执行 V1 与 V2。[Spring Boot 4 的 Flyway 配置](https://docs.spring.io/spring-boot/4.0/appendix/application-properties/)

账号内部接口位于 `/internal/accounts/**`，网关不提供该路由。其随机内部密钥由启动脚本生成，保存在忽略的本地配置中；该接口只能管理 MEMBER / COACH，不能创建管理员。浏览器所有写操作必须校验 CSRF，即使认证来自 JWT Cookie 也不跳过；登录、退出与档案服务使用同名的 CSRF Cookie 和指定请求头。

## 验收与运行

```powershell
.\scripts\start-stage2.ps1
.\scripts\verify-database.ps1
.\scripts\verify-chain.ps1
# 建立本文演示档案之后，可验收真实接口：
.\scripts\verify-management.ps1
```

本地模式自动给已有 `member`、`coach` 演示账号补齐档案，不重置账号或修改已有资料。管理员账号仍是 `admin` / `FlowYoga@123`。

测试覆盖两类档案正常创建、重复提交、账号/手机号冲突、待同步时阻止第二次修改、版本冲突、初始密码不入任务、账号激活超时恢复、服务重启后的未知结果关闭、关闭编号阻止迟到创建、停用撤销会话、恢复账号不恢复旧会话、直接服务鉴权、跨角色拒绝和 CSRF。真实浏览器验收还须检查列表、筛选、表单保存和状态切换，运行结果写入技术验证文档。

本次已通过页面建立 `demo.xuan`（演示会员）和 `demo.muyu`（演示教练），初始演示密码为 `FlowYoga@123`。`verify-management.ps1` 仅操作指定的 `demo.*` 账号，临时启用、停用来检查会话撤销，最后恢复原启停状态；不修改其他账号。换电脑运行时须先通过页面建立这两份演示档案，或用脚本参数指定其他 `demo.*` 演示账号。
